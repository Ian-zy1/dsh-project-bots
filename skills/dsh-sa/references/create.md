# 创建需求

用于形成计划、发布固定快照及获批后的派活。已完成的阶段用原产物继续，只补缺项。

1. **明确计划。** 读项目规则、相关需求和源码。复用该项目连接，只有缺失或变更时才加载 [初始化](init.md)。确认目标仓库、完整基线 SHA、变更范围、验收和定向验证命令。简单需求一个任务；只有可独立交付或并行的工作才拆分。工具链、新模块或依赖变化时核对对应缺口。
2. **固定快照。** 按 [AW 字段和交付约定](aw.md) 在现有任务说明和验收中写清业务边界、验证与独立评审要求。说明开头用一句「改哪里、改什么、结果如何」。保留原需求引用。需要发布或回读时查 [快照命令](operations.md#2-发布并回读快照)，核对项目、目标仓、完整基线、版本、摘要与验收。用户只要计划时到计划为止。
3. **确认后派活。** 出示计划、固定版本、待发文案和目标 Bot。默认等用户批准该版本和阶段；已明确授权直接派活时按授权处理，实质改范围或版本时重新确认授权。新发送前检查当前运行态，按用户指定入口或项目 `preferredChannel` 只读 [飞书](feishu.md) 或 [钉钉](dingtalk.md)。已批准的本地计划直接交 Worker 实施；仅远端计划才用 `phase=plan`。
4. **交接。** 飞书启用自动绑定时，用固定快照预览，保存送达回执即结束当前轮，接单由 DSH 与 Relay 完成。旧版入口按通道说明关联原 Ticket/Session。区分发送、接单和 Worker 读取证据；未知状态按原消息与原幂等键查证。

## 输出模板

- 计划：目标、范围、验收、验证命令。
- 固定任务：项目/仓库、基线 SHA、AW 任务链接和版本。
- 派活：目标 Bot 和待发文案，或已发送的回执与下一阶段。
